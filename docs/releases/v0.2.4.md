## The Order: 1886 — v0.2.4

Builds on [v0.2.3](https://github.com/JulioCacko/The-Order-1886_pc/releases/tag/v0.2.3). From [#117](https://github.com/JulioCacko/The-Order-1886_pc/pull/117), which fixes [#114](https://github.com/JulioCacko/The-Order-1886_pc/issues/114).

### Linux without WebKitGTK 4.1 (SteamOS, Steam Deck)

Before this release, the Linux package did not start at all on a system without WebKitGTK 4.1, such as SteamOS. Both `The Order 1886` and `Play The Order 1886` were the launcher window's own binary, so the dynamic linker refused both:

> libwebkit2gtk-4.1.so.0 => not found

Both entry points are now a separate build that links no WebKitGTK and no GTK. The launcher window moved to `bin/order1886-launcher`.

- `The Order 1886` opens the launcher window when the system has WebKitGTK 4.1. When it does not, it names the missing library and then plays with the saved settings. The message also goes to a desktop dialog or notification when one is available, and to `user/order1886/logs/launcher-entry.log`.
- `Play The Order 1886` starts the game directly, as on Windows.
- `--game-dir /path/to/game` sets the game folder without the launcher window, for example in the Steam launch options. The folder is checked and saved; a folder that is not a game is refused and the saved one is kept.
- A game folder of any name next to the package folder is found without setup.

The new `QUICKSTART.txt` in the Linux package covers SteamOS and Steam step by step.

### Linux: the game would not start from the package

Testing this release showed a second fault in every earlier Linux package: the game stopped with "Order runtime not found in this installation", because the backend looked for the runtime one folder too deep. This is fixed. Windows was not affected.

### Unchanged

The launcher window on SteamOS still needs WebKitGTK 4.1; issue #114 describes a Homebrew workaround. 60 FPS and above are still experimental, and the published 60 FPS patch warns of QTE softlocks in Chapters 6 and 9.
