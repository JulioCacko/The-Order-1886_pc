## The Order: 1886 — v0.2.6

Builds on [v0.2.5](https://github.com/JulioCacko/The-Order-1886_pc/releases/tag/v0.2.5). A fix release for [#131](https://github.com/JulioCacko/The-Order-1886_pc/issues/131), [#127](https://github.com/JulioCacko/The-Order-1886_pc/issues/127), [#133](https://github.com/JulioCacko/The-Order-1886_pc/issues/133) and [#134](https://github.com/JulioCacko/The-Order-1886_pc/issues/134).

### Folder buttons and updates work (#131)

- **Open installation**, **Open logs** and **Open player data** open the folder in Explorer (or your file manager on Linux). They did nothing before, without an error.
- **Check for updates** now says **Up to date** when you already have the latest release, and the update banner goes away. Before, v0.2.5 reported itself as an update forever.
- The "Checking for updates…" footer clears when the check finishes, the download shows its progress from the first second, and both buttons stay disabled while either runs. A second click can no longer break a running download.
- A download no longer fails after 10 minutes on a slow connection; it fails only when no data arrives for a minute, with a message saying so. Downloads are refused while the game runs.

### A wrong runtime pick is refused when you choose it (#127)

System → **Runtime executable** used to accept any `.exe` and fail only at Play with "not a verified dedicated Order runtime". Choosing the launcher's helper (`order1886-worker.exe`), a runtime without its `runtime-build.json`, or files from different builds is now refused when you save it, with the reason. **Use installation runtime** clears the setting. Leaving it empty is still the right choice for almost everyone.

When the game window is closed (close button, Alt+F4 or a system quit), the log now says so and the launcher shows it as the reason the session ended. Before, the session ended with exit 0 and no explanation.

### Fewer GPU-library stops (exit 23) (#133)

- A shader that reads through a pointer outside GPU memory, or into memory nothing maps, now reads zeros, as the PS4's GPU does. Before, it stopped the game with "STOP: GPU library assertion failed". The only exit 23 recorded at 3840×2160 was this stop.
- Fixes ported from [SpartanPort](https://github.com/FelipePrado0/SpartanPort) PR #1124 close other exit-23 paths: recording data larger than one 128 KiB chunk, a draw-queue race on CPUs with 8 or more threads, texture views past the end of their image, cached images missing layers, padding-only overlaps, out-of-range image slots, and packet sizes read after the packet ran.
- The crash reported in #133 did not reproduce on our hardware, so these fixes are not confirmed against it. If you still see exit 23, attach the boot log from `user/order1886/logs`; to add a crash dump, set `ORDER1886_FATAL_DUMP` to a new file path (for example `C:\order1886-crash.dmp`) before starting the launcher.

### CPU use on 6-thread processors (#134)

- The game's audio threads run at above-normal priority, the GPU thread backs off instead of spinning while it waits, and the game's job threads sleep after long runs of yielding.
- The boot log now ends with CPU time per thread and yield counts. On a 6-core CPU with high CPU use, attach that log: it shows which threads take the time.
- On our test CPU limited to 6 and 4 threads, total CPU use did not measurably drop. Treat this as a first step, not a fix. Details: [thread priority verification](https://github.com/JulioCacko/The-Order-1886_pc/blob/main/docs/verification/2026-10-31-thread-priorities.md).

### Unchanged

60 FPS and above are still experimental, and the published 60 FPS patch warns of QTE softlocks in Chapters 6 and 9. Render sizes other than Original, and turning post effects off, remain experimental. The launcher window on SteamOS still needs WebKitGTK 4.1.
