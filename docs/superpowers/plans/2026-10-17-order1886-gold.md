# The Order: 1886 gold implementation

## Accepted contract

Implement every open issue in JulioCacko/The-Order-1886_pc (#1-23 at planning),
including newly discovered blockers. Find working solutions; do not close requests
as infeasible. Preserve original game files, player data and existing work.
Use the current Python/Tkinter launcher, shared backend and Vulkan runtime.

- Required game builds: CUSA00076 APP_VER 01.00 / VERSION 01.03 and update 01.02.
- Default: original framing and native 30 FPS; preserve explicit saved choices.
- Requested timing modes: 30, 60, 90 and unlocked with a default 120 FPS cap.
  Diagnose the reported 40 FPS rejection; adding 40 FPS is not requested.
- Preserve signature/hash guards. Patches affect derived images only.
- Use RenderDoc, Ghidra 12.1.4/GhidraMCP, WinDbg and ETW for relevant evidence.
  Start offline; use one instrument at a time in bounded isolated live runs.
  Stop instrumented work on renewed system instability.
- Stage local hardware qualification, then require vendor-specific hardware
  evidence before accepting wider support claims. Frame generation is excluded.
- Deliver reviewable batches and local PR/issue evidence; no public posting,
  merge or release publication is authorized by this plan.

## Verification

For each defect: reproduce or create an equivalent fixture, observe the focused
regression fail, fix the shared source, rerun the regression and affected suites.
Keep runtime/build/config/game identities with every artifact. Historical captures
are diagnostic leads and cannot certify a changed build.

- Four human campaign runs: native 30 and selected 60 FPS profile on both builds.
- Stress matrix for every advertised provider/rate/aspect: combat, camera motion,
  cinematics, HUD/subtitles, input/audio/timing, saves/reload and Chapter 6/9 QTEs.
- 4K/60: 3840x2160 output (FSR1 accepted), preserve original detail/effects,
  30 minutes representative gameplay, average >=59 FPS, p99 <=20 ms; report cold
  and warm cache separately and measure distinct guest rendering.
- Native checks, Python tests, packaged portable checks, manifests and rollback.
  Test skipped/unavailable dependencies remain explicit gaps.
- Human testers judge perceptual quality; automated tests/replays collect repeatable
  evidence. Hardware-specific modes cannot inherit another provider's acceptance.
