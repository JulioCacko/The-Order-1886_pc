# PS4 save import conversion findings

Research date: 2026-10-17

## Recommendation

No verified Windows-only offline converter was found that takes the supplied `Playthrough00` and `Profile` PFS images plus their `pfsSKKey` sidecars and emits the decrypted directory format expected by this runtime. The most supportable path is Apollo Save Tool on a compatible homebrew-enabled PS4, followed by a check/adaptation of the resulting metadata for this runtime. The exact supplied files have not been tested with Apollo.

## Evidence

- The task evidence identifies each save image as 10 MiB, with a 96-byte companion whose magic is `pfsSKKey` and keyset bytes `05 00`. The PS4 Developer Wiki documents `pfsSKKey` as a sealed key, and the save-data format associates sealed-key sidecars with PFS save images: [sealed key format](https://www.psdevwiki.com/ps4/Sealedkey_/_pfsSKKey), [save-data layout](https://www.psdevwiki.com/ps4/Save_Data). This identifies the companion as key metadata, not a decrypted save.
- The source for [PSFSKKey](https://github.com/cfwprpht/PSFSKKey) is not a complete converter. Its README says SAMU PFS keys are missing and instructs users to supply savedata master keys (or obtain them through a console dump). Its [Program.cs](https://github.com/cfwprpht/PSFSKKey/blob/master/Program.cs) reads the keyset byte, loads `savedatamasterhashkeyN.bin` and `savedatamasterkeyN.bin`, validates the HMAC, and derives/prints PFS key material. At lines 124-145, the actual filesystem decryption is explicitly a TODO and its code is commented out. It does not enumerate/extract files or create a decrypted save directory. Do not use it as the import converter.
- [flatz/pkg_pfs_tool](https://github.com/flatz/pkg_pfs_tool) is a PS4 PKG/PFS tool and its README describes a Windows cross-build. Its [configuration](https://github.com/flatz/pkg_pfs_tool/blob/master/config.ini) accepts package passcodes/image keys or final PFS encryption keys. The reviewed docs do not describe consuming a save's sealed `pfsSKKey` sidecar or producing the required save-directory layout, so this is not evidence of a supported save converter.
- [Apollo Save Tool (PS4)](https://github.com/bucanero/apollo-ps4) is the practical candidate. Its README says it can decrypt/export saves and import decrypted saves. The project's [usage guide](https://github.com/bucanero/apollo-ps4/blob/main/docs/usage.md) describes encrypted USB saves under `/PS4/SAVEDATA/<ACCOUNT-ID>/<title-id>/`, and its decrypted output under `/PS4/APOLLO/<USER-ID>_<title-id>_<Save-name>` with save files and an `sce_sys` folder. It says encrypted saves acquired from retail consoles must be from firmware 11.00 or lower. The guide uses Apollo's `Copy save game` action for importing/exporting these saves. This is a PS4 application, not a Windows converter; the guide's described path requires a PS4 capable of running Apollo.
- [Playstation 4 Save Mounter](https://github.com/ChendoChap/Playstation-4-Save-Mounter) is an older Windows UI that connects to a PS4 running `ps4debug` and FTP. Its README requires a PS4 5.05 setup, says it cannot be used on an unexploited console, and limits decrypted copies to saves encrypted with keys up to 5.05. It is console-assisted, not an offline Windows converter. The sidecar's keyset value alone does not prove compatibility with that firmware limit.

## Safe workflow if a compatible PS4 is available

1. Preserve the original files and work from a copy. Apollo's guide expects a complete encrypted save in the standard USB hierarchy `/PS4/SAVEDATA/<ACCOUNT-ID>/CUSA00035/`. The account ID is part of the input path; the guide describes it as a 16-hex-character ID. Do not invent one. If the supplied directory contains only the two PFS images and sidecars, it is not enough to establish that the full Apollo input (including save metadata) is present.
2. On a PS4 that can run Apollo, use its USB Saves view to select the encrypted save and copy it to the console. Apollo documents this path for retail encrypted saves up to firmware 11.00, but support for these exact files remains unverified.
3. Use Apollo's `Copy save game` action to export a decrypted copy to USB. The documented output is `/PS4/APOLLO/<USER-ID>_CUSA00035_<Save-name>` containing files and `sce_sys` metadata.
4. Import that output into a new runtime save folder only after checking it against the runtime's required layout. The runtime source expects `<user>/savedata/<user-id>/CUSA00035/<save name>/` plus `<save name>.sce_sys/param.bin` and `icon0.png` ([runtime loader](/D:/Emulator/The-Order-1886_pc/src/runtime_savedata.c), [directory-only backup/restore](/D:/Emulator/The-Order-1886_pc/scripts/save_backup.py)). Apollo documents standard PS4 `sce_sys` output; its guide does not claim to produce this runtime's separate `.sce_sys/param.bin` layout, so a metadata mapping may still be needed.

## Conclusion and limits

PSFSKKey is only a sealed-key proof of concept and cannot complete PFS filesystem decryption even when its required master-key files are supplied. Apollo is the best documented conversion route if the user has a compatible PS4 and a complete save export; it has not been confirmed against these specific `CUSA00035` files. If no such PS4 is available, the reviewed primary sources do not establish a safe supported offline converter. Keep the input files unchanged and do not treat a key-printing tool as a converter.
