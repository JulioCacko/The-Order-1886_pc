## Mapped-range optimization follow-up

The street trace led to a bounded per-thread cache for exact one-byte probes.
Entries use the existing even mapping-table generation, including negative
results, and fall back to the normal locked lookup on a miss. Generic ranges
keep the existing adjacency/gap rules and perform one binary search instead of
two. The disabled-optimization switch still bypasses both caches.

`mapping-cache-red.log` records two failing production-source regressions before
the change: 32 cold probes performed 64 searches, and a repeated 32-image working
set performed 128,000 searches for 64,000 probes. The corrected fixture performs
32 searches for those 64,000 probes. `mapping-cache-benchmark.json` records nine
runs of each exact source variant against 1,024 synthetic VMAs; this is not a
measurement of the game's actual address distribution or FPS.

Four focused tests pass, covering generic ranges, gaps/reservations, exact-address
hash collisions, negative-result invalidation, odd writer epochs, the disabled
switch, and mapping changes published by another thread. Independent review found
no actionable defect. `python-mapping-final.log` records 309 tests with 28 skipped
and no failures; `native-mapping-cache-build.log` records 15 passing native checks.
Runtime SHA256: `8327bc087eaf3b7d41bd4b785d2da33b7cb5e9eacda1a8a4bb6b070d52abe538`.

The package `20261018T140956Z-8327bc087eaf` contains this runtime and the complete
launcher/helper batch. All 15 relocated portable smoke checks passed, including
manifest hashes, helper closure, GUI/direct-play startup, and guarded 30/60
preparation (`portable-mapping-final/*/smoke-report.json`). These checks do not
establish gameplay performance. A same-viewpoint street frame-time comparison remains

## Deferred-street automated checks

The user deferred the street comparison and requested continued automated checks.
The previous 28 skips consisted of 17 ISA tests missing `iced-x86` in the default
Python and 11 tests missing Windows runtime/semaphore binaries. The existing
package Python environment supplies the dependency; all 21 ISA-rewrite tests ran
and passed there without installing packages globally.

Windows CMake and `build.sh --test` now include the existing real runtime/semaphore
fixtures. Python native-test paths select `out/gpu/*.exe` and use the CLANG64 DLL
environment, including the current content-test binary instead of a stale copy.

Enabling these tests exposed a real busy-mutex destruction defect. On this host,
`pthread_mutex_destroy` returned success after a recursive mutex had been locked
twice. The runtime consequently freed a still-used guest handle. The original
runtime assertion and a focused three-mutex-type regression failed before the fix
(`runtime-mutex-red.log`). The owned CPU-fixture dump and WinDbg MCP confirmed the
assertion location; incorrect/missing OS symbols in automatic analysis were not
used to identify the cause. No game process was attached or controlled.

The runtime now counts active acquisitions, recursive locks, and blocked waits,
rejects their destruction with `EBUSY`, and balances failed/timed acquisitions and
successful unlocks. Condition waits retain their reference across native release
and reacquisition. Eight runtime tests pass, including timed-lock failure,
condition timeout, preserved handles, recursive depth, and destroyed-handle errors.
The busy-mutex regression is also part of the default native runtime fixture.
Independent review found no blocking issue. Existing arbitrary/concurrent handle
destruction hazards are not established as resolved by this change.
