# Bounded HTILE metadata adaptation

This follow-up adapts the uniform HTILE read idea from [mateussmeneses/theorder1886-port](https://github.com/mateussmeneses/theorder1886-port) `3654b0622aaa7648ee07c8dd493d9b0300ef1b6f` (original diagnosis: TOport `94e3c22` and `dfc66af`, [IgorAugustoHH/The-Order-1886-PC-Port](https://github.com/IgorAugustoHH/The-Order-1886-PC-Port): HTILE read as a plain buffer sees every tile as cleared, since nothing writes HTILE when depth is drawn) without its unchecked optional-value dereference. The reviewed fix pass limits synthesis to one verified layer. It does not qualify shadow rendering or complete HTILE emulation, and remains isolated from published packages.

The metadata registry records the owning image UID, type, layer count, stencil format and the byte extent observed at a metadata clear. Rebinding the same owner preserves state; replacing ownership or geometry resets derived words. An old image cannot erase its replacement's entry. Unmapping metadata bytes removes the entry even if the depth image lives elsewhere. Temporarily disabling metadata in a binding retains the association, as the underlying allocation still exists.

Known, aligned, bounded single-layer HTILE reads can synthesize conservative full-range depth words. Unsupported layer counts, oversized/unknown extents and shader-written data retain the normal buffer path. Unsupported clears execute the original shader; synthesis never seeds multilayer buffers with clear words that would become stale after a slice is drawn. Clear recognition must handle every write destination and its fully mapped byte range before skipping a dispatch, including a shader mixing supported and unsupported metadata destinations. Depth writes update every layer in the attachment view; read-only depth bindings preserve clear state.

Uniform skipped clears and changed draw states materialize through the existing GPU buffer machinery. Uploads preserve neighboring bytes, normal page tracking observes CPU overwrites, selective mode watches small generated buffers, and GPU byte ranges participate in downloads/unmaps. Buffer writes, storage-image bindings, explicit fills/copies and CPU invalidations cancel derived metadata. GPU publication alone does not count as a new shader write. Explicit non-clear HTILE fills keep their real words. Up to eight materializations are logged for bounded runtime evidence.

The registry lock now spans final word validation, upload synchronization, fill and GPU ownership publication. CPU writes and unmaps invalidate derived metadata before buffer readback/retirement, and do not hold the registry lock while waiting on GPU work. This closes the stale snapshot window. The lock audit found guest VM API input/output accesses under VM locks; that independent prerequisite was reproduced with actual protected pages, fixed, reviewed and merged in PR #31. Backing uploads bypass protected guest views; queued readback retirement and buffer fill do not enter the texture registry while the metadata lock is held.

The permanent CPU model regression checks clear/draw transitions, stencil words, bounded reads, zero/wrapping ranges, overlapping metadata registration, shader writes, image UID reuse, geometry changes, unmap and concurrency. Compiled production recognizer/materialization paths check unsupported clears, both mixed-destination orders, upload-before-fill, selective watches, GPU ownership, neighbor preservation, invalidation between lookup and fill, and a CPU write arriving during fill. A separate production invalidation fixture verifies metadata cancellation precedes buffer readback. The original failures were observed before the fixes. These are CPU fixtures, not Vulkan or visual evidence.

Initial checks passed 365 Python tests and 45 native checks. Fresh review found three Important defects; the single fix pass reproduced them, the mixed-destination variant and the partially mapped clear range with failing regressions. The combined final rerun passes 377 Python tests with zero skips in 82.875 seconds, all 46 Windows native checks and the runtime build. This establishes fixture coverage, not gameplay or performance qualification. The graph service remains unavailable (`Transport closed`); exact source and caller searches cover this bounded scope. No second review replaces the failing-then-passing regressions.

## Qualification still required

- Multilayer HTILE synthesis remains incomplete. Unsupported clears execute real shaders; a verified slice/tile layout is still required before extending synthesis.
- Conservative uniform min/max and stencil words need matched gameplay/capture acceptance. Synthetic words can introduce buffer fills and synchronization costs; performance must be measured.
- Metadata-clear shader recognition retains the existing heuristic. Its exact game shader inputs and output ranges need runtime evidence.
- No shadow, aiming, FPS, temporal-provider, campaign, update 1.02 or Gold claim follows from these checks. No new player option is introduced by this internal correctness change.
