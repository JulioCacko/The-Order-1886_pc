# Guest memory API publication outside internal locks

The HTILE lock audit found a runtime memory boundary that also affects existing GPU synchronization: exported memory APIs read or write guest result pointers while holding the VM table or mapping lock. A GPU-protected guest output can fault back into GPU work needing those locks. This is independent of whether HTILE synthesis is enabled.

Direct allocation now publishes its result after releasing the VM lock. Direct/flexible mappings and reservations snapshot the requested address before acquiring locks and publish successful results after releasing locks and completing GPU notifications. Protection, virtual-memory and physical-memory queries snapshot their result under the table lock and copy it to guest outputs after unlocking. Batch operations use a host-owned input snapshot and copy only successful mapping-address results back afterward; partial completion counts, failed-entry values, unrelated fields, native error codes and ordered GPU notifications remain intact.

The native fixture protects actual output pages and installs a Windows access-violation handler or Linux SIGSEGV handler. It checks that neither internal lock is held when a guest input/output fault occurs. The initial fixture needed the runtime's Windows high-entropy-VA linker setting before it could reserve the PS4 address space; after that correction, it failed on the original allocation's `exclusive_depth` assertion. The fixed APIs pass 13 protected accesses across allocation, mappings, reservations, queries, batch input/output and partial failure. A separate regression failed when an invalid zero-size mapping unnecessarily read a protected input; shared scalar validation now rejects that request before dereferencing its pointer.

Focused backing-read and mapping-ownership regressions pass. The full Python suite passes 373 tests with zero skips in 92.720 seconds. All 45 Windows native checks pass, and the runtime builds. Both the standalone and CMake fixture use the runtime's required Windows high-entropy-VA linker setting; the first native run failed address reservation before that CMake setting was added. Hosted Linux and fresh-review evidence follow separately. Batch mapping adds one temporary host allocation per call; allocation failure returns the existing out-of-memory code without changing guest entries. No launcher settings, cache policy or save behavior change. No Chapter 2 FPS gain, gameplay result or Gold qualification is claimed.

The HTILE fix pass remains isolated and unpublished while this boundary and its lock ordering are verified.
